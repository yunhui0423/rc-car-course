# 個人練習題與參考解答

每題先寫預測，再動手；故障實驗在馬達斷電時進行。

## 第1堂

1. 自己兩端車號相同，另一人車號不同。為什麼要同時區分頻道與位址？
2. 發送端ACK=1是否證明程式已讀封包？是否證明馬達在轉？
3. 將PingRx車號改錯，記錄100筆；復原後再記錄100筆，比較成功率。
4. 100筆中97筆ACK成功，成功率是多少？如果所有ACK成功但畫面缺號，還應檢查什麼？

## 第2堂

1. `analogRead`中心是503，讀值535，死區±60，命令是多少？
2. PWM0、60、100各佔255多少比例？為什麼占空比不是實測速度？
3. 油門80、轉向20時左右命令各多少？油門120、轉向120會得到什麼？
4. Bench的SW為何接Uno D12，第3堂卻接Nano D2？

## 第3堂

1. 當次ACK中的seq落後於剛送出的seq，是否一定是錯誤？
2. 為什麼失聯恢復後仍按住推桿時不應自動啟動？
3. 將遙控器關閉，架空測停止延遲；拍攝畫面並說明時間量測誤差。
4. 能否用這份回報直接畫電池電壓或公尺/秒？缺少什麼？

<details>
<summary>完成練習後展開參考解答</summary>

- 第1堂：頻道是無線頻率設定、位址篩選接收資料，兩端仍須相容速率與格式。ACK是晶片層確認，不能證明主程式完成，更不能證明實體馬達動作。97/100=97%；序列監控、主程式讀取與顯示遺漏也需排查。
- 第2堂：535-503=32，落死區，輸出0。0%、約23.5%、約39.2%；負載、電壓與摩擦都影響速度。左右100/60；120+120限制為120、120-120為0。兩個SW接法是不同課次、不同板；Uno D2用於馬達，Uno D12在第3堂作SPI MISO，必須移線。
- 第3堂：ACK預載，因此通常帶前次處理狀態；按seq比對。恢復後須先回中與放開，避免突然移動。500ms是程式門檻，實際時間包含排程、無線與量測誤差；STBY低時還有滑行。要量車速需編碼器等感測，要量電壓需適當分壓與校正；本包都沒有。

</details>
